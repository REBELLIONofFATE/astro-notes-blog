# 分类系统与笔记同步方案

## 一、背景

当前博客（Astro 静态站点）仅有 3 篇手写的示例文章，存放在 `astro-blog/src/content/posts/` 下，没有分类、标签、分页功能。

另有一个独立的笔记仓库（`/Users/wuyuxiang/Desktop/myNote/myNote`），包含 264 篇 Markdown 笔记，按技术主题组织为 22 个目录（Docker、redis、spring-ai-alibaba、服务器、算法等）。笔记没有 frontmatter，直接以 `# 标题` 开头。

目标：将笔记仓库的内容接入博客，利用目录结构自动生成多级分类，并以树状侧边栏展示。

---

## 二、核心设计思路

### 2.1 目录即分类

不在 frontmatter 中手动维护 category 字段，而是从文件路径自动推导分类层级：

```
笔记仓库目录结构                    →  博客分类
─────────────────────────────────────────────────
Docker/Docker安装.md                →  Docker
redis/springboot整合redis.md        →  redis
spring-ai-alibaba/ai认识与了解.md   →  spring-ai-alibaba
服务器/vim编辑器.md                 →  服务器
文档/pdfs/注解.md                   →  文档 > pdfs
hello-world.md（根目录）            →  未分类
```

### 2.2 标签走 frontmatter

标签（tags）与分类不同，一篇文章可以有多个标签，且标签是跨分类的。标签信息通过 frontmatter 的 `tags` 字段定义，设为可选，默认空数组。

### 2.3 纯静态，无后端

所有数据在 `astro build` 时生成，不需要后端服务、数据库或 API。构建 264 篇文章预计耗时约 10 秒。

---

## 三、笔记同步方案

### 3.1 方案选择：自定义 Astro Content Loader

不使用外部同步脚本，而是编写一个自定义的 Astro content loader，在构建时直接从笔记仓库路径读取文件，自动补全缺失的 frontmatter 信息。

优势：
- 不需要额外的构建步骤
- 不需要在博客仓库中复制笔记文件
- `astro build` 或 `astro dev` 时自动加载最新内容

### 3.2 Loader 核心逻辑

```typescript
// src/loaders/notes-loader.ts（伪代码）
export function notesLoader(options: { basePath: string }) {
  return {
    name: "notes-loader",
    async load({ store }) {
      // 1. 递归扫描 basePath 下所有 .md 文件（排除 .git、文档 等非笔记目录）
      // 2. 对每个 md 文件：
      //    - 解析是否有 frontmatter，有则使用，无则自动生成
      //    - title: 从文件第一个 # 标题提取，fallback 到文件名
      //    - slug: 从文件相对路径生成 URL 安全的 slug
      //    - date: 从 git log 获取首次提交时间，fallback 到文件 mtime
      //    - category: 从目录路径推导，如 "Docker" 或 "文档/pdfs"
      //    - tags: 从 frontmatter 读取，默认 []
      //    - draft: 默认 false
      // 3. 存入 store
    }
  };
}
```

### 3.3 需要过滤的内容

| 过滤规则 | 说明 |
|---------|------|
| 非 .md 文件 | 排除 PDF、DOCX、图片等（约 84 个文件） |
| `文档/` 目录 | 主要是 PDF 参考资料，非笔记内容 |
| `.git/` 等隐藏目录 | 排除版本控制文件 |
| 可配置排除列表 | 通过配置文件指定需要排除的目录或文件 |

### 3.4 Content Schema 调整

```typescript
// src/content.config.ts
const posts = defineCollection({
  loader: notesLoader({ basePath: '/Users/wuyuxiang/Desktop/myNote/myNote' }),
  schema: z.object({
    title: z.string(),
    slug: z.string(),
    date: z.coerce.date(),
    draft: z.boolean().default(false),
    category: z.string().default("未分类"),    // 新增
    tags: z.array(z.string()).default([]),      // 新增
  }),
});
```

## 四、分类树数据结构

### 4.1 树节点定义

```typescript
interface CategoryNode {
  name: string;            // 显示名称，如 "Docker"
  path: string;            // 完整路径，如 "文档/pdfs"
  count: number;           // 该分类下文章总数（含子分类）
  children: CategoryNode[];// 子分类
}
```

### 4.2 构建时机

在每个需要侧边栏的页面的 frontmatter 脚本区计算：

```astro
---
const allPosts = await getCollection("posts");
const tree = buildCategoryTree(allPosts);
---
<Sidebar tree={tree} />
```

`buildCategoryTree` 是纯函数，遍历所有文章的 category 字段，按 `/` 分割构建树。264 篇文章构建树的耗时可忽略（< 1ms）。

## 七、分页

首页和分类页面引入分页，使用 Astro 内置的 `paginate()` 函数：

- 每页显示 10 篇文章
- 路由格式：`/page/2`、`/categories/Docker/page/2`

## 八、自动构建流程

```
笔记仓库 git push
       ↓
触发博客仓库 CI（webhook / repository_dispatch / deploy hook）
       ↓
CI 流程：
  1. checkout 博客仓库
  2. 配置笔记仓库路径（CI 中 clone 笔记仓库到临时目录）
  3. npm run build（Astro 构建时 loader 自动读取笔记）
  4. 部署 dist/ 到目标平台
```

本地开发时，loader 直接读取本机笔记仓库路径，无需额外操作。
