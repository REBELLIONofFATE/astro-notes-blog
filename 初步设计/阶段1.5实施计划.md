# 阶段 1.5 实施计划：笔记同步 + 分类系统

> **定位**：阶段 1（核心博客）的延伸，仍为纯静态方案，`astro build` 时完成所有数据处理，不引入数据库和后端服务。
>
> **前置条件**：阶段 1 已完成（首页、文章详情页、RSS、工具函数均可用）。

---

## 总体原则

- **单一事实源**：Git + Markdown 是唯一内容源，构建期解析，不依赖外部系统
- **零迁移成本**：264 篇无 frontmatter 的笔记，loader 自动补全，不修改原始文件
- **纯静态输出**：所有分类、标签、分页页面均在构建期生成，无运行期依赖
- **不提前设计**：不引入数据库、不做评论/搜索，这些留给阶段 2 和阶段 4

## Step 1 — 编写 `notes-loader.ts`（核心前置）

**文件**：`src/loaders/notes-loader.ts`

**职责**：替换现有 `glob` loader，在构建时直接从笔记仓库路径读取文件，自动补全缺失的 frontmatter。

### 接口设计

```typescript
interface NotesLoaderOptions {
  basePath: string;          // 笔记仓库根目录的绝对路径
  excludeDirs?: string[];    // 需要排除的目录名，默认 ['.git', '文档']
}

export function notesLoader(options: NotesLoaderOptions): Loader
```

### 每个 md 文件的处理逻辑

| 字段 | 来源 | 备注 |
|------|------|------|
| `title` | 文件第一行 `# 标题` | fallback 到文件名（去扩展名） |
| `slug` | 文件相对路径转 URL 安全字符串 | 中文转拼音或保留，`/` 替换为 `-` |
| `date` | `git log` 首次提交时间 | fallback 到文件 `mtime` |
| `category` | 父目录路径（相对 basePath） | `Docker/子目录/文件.md` → `Docker/子目录`，根目录文件 → `未分类` |
| `tags` | frontmatter `tags` 字段 | 无 frontmatter 时默认 `[]` |
| `draft` | frontmatter `draft` 字段 | 默认 `false` |
| `type` | frontmatter `type` 字段 | 默认 `note`，可选 `featured`/`note` |

### 过滤规则

```
排除：非 .md 文件（PDF、图片、配置文件等）
排除：excludeDirs 中指定的目录（默认 .git、文档）
排除：以 . 开头的隐藏目录
```

### basePath 配置方式

```typescript
// astro.config.mjs 中统一配置
const NOTES_BASE_PATH = process.env.NOTES_PATH ?? 'D:\\path\\to\\myNote';
```

本地开发写死本机路径，CI 通过环境变量 `NOTES_PATH` 注入。

### 验收标准

- `astro dev` 启动后，笔记仓库中的 md 文件出现在文章列表中
- 无 frontmatter 的笔记能正确提取 title、生成 slug、推导 category
- 草稿过滤（`draft: true`）仍然正常工作

## Step 3 — 新增 `categories.ts` 工具函数

**文件**：`src/utils/categories.ts`

```typescript
interface CategoryNode {
  name: string;             // 显示名称，如 "Docker"
  path: string;             // 完整路径，如 "文档/pdfs"
  count: number;            // 该分类下文章总数（含子分类）
  children: CategoryNode[];
}

// 从所有文章构建分类树（纯函数，< 1ms）
export function buildCategoryTree(posts: Post[]): CategoryNode[]

// 根据路径获取该分类下的所有文章（含子分类）
export function getPostsByCategory(posts: Post[], categoryPath: string): Post[]

// 获取所有标签及其文章数
export function getAllTags(posts: Post[]): { tag: string; count: number }[]
```

### 验收标准

- 分类树结构与笔记仓库目录层级一致
- 空分类（无 public 文章）不出现在树中
- `count` 值与实际文章数一致
