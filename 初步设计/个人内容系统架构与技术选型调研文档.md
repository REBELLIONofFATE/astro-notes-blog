# 个人内容系统（长期工程）

> **用途说明**  
> 本文档用于记录在开发前阶段，对个人长期内容网站（笔记 / 文章）的 **架构设计、技术选型、风险评估与演进路线** 的调研结论。  
> 目标不是“最快上线”，而是 **可长期维护、可演进、可作为工程能力训练载体**。

---

## 1. 项目目标与定位

### 1.1 项目定位

- **个人长期工程**（非一次性博客）
- 内容以：
  - 技术笔记
  - 长期文章
  - 架构/工程总结
- 单人开发、单人维护
- 可作为：
  - 架构设计练习
  - 构建系统练习
  - 内容系统建模练习

---

### 1.2 核心目标

| 目标 | 说明 |
|---|---|
| 内容可控 | 内容不依赖第三方平台 |
| 长期可维护 | 5 年后仍可理解和维护 |
| 架构清晰 | 职责边界明确 |
| 可演进 | 支持未来复杂需求 |
| 工程价值 | 不只是“能用” |

---

## 2. 总体架构概览

### 2.1 架构总览

```
Typora / 编辑器
   ↓
Markdown + Frontmatter
   ↓
Git（唯一事实源 / SSOT）
   ↓
服务器同步仓库（git pull）
   ↓
内容同步工具（md → DB）
   ↓
Astro 构建静态页面（SSG）
   ↓
Vue（前端交互组件）
   ↓
Spring Boot API
   ↓
MySQL（关系 / 业务数据）
```

---

### 2.2 架构设计原则

1. **单一事实源（SSOT）**  
   - Markdown 是唯一内容源
   - 数据库数据必须可从 md 完全重建

2. **单向数据流**  
   ```
   md → DB → 页面
   ```

3. **构建期与运行期严格隔离**

4. **派生数据不反向影响源数据**

5. **失败可恢复、系统可重建**

---

## 3. 内容系统设计

### 3.1 内容存储策略

| 内容类型 | 存储位置 | 说明 |
|---|---|---|
| 正文 | Markdown 文件 | 唯一权威 |
| Frontmatter | Markdown 文件 | 内容声明 |
| 标签/分类关系 | MySQL | 派生关系 |
| 访问量等 | MySQL | 业务数据 |

---

### 3.2 Frontmatter 设计规范

```yaml
---
id: post-xxx
title: 示例文章
slug: example-post
date: 2026-01-02
tags:
  - 架构
  - Markdown
category: 工程
draft: false
---
```

#### 设计原则

- 字段 **白名单化**
- Frontmatter 只做「声明」
- 不承载业务逻辑

---

### 3.3 内容目录结构（建议）

```
content/
├─ posts/        # 正式文章
├─ notes/        # 个人笔记
└─ drafts/       # 草稿
```

## 4. 构建系统设计

### 4.1 构建阶段职责

| 阶段 | 职责 |
|---|---|
| 构建期 | md → HTML / md → DB |
| 运行期 | API / 查询 / 业务逻辑 |

---

### 4.2 构建流程

```
1. git pull
2. 计算 md 变更（git diff）
3. 解析 Frontmatter
4. 同步派生数据到 DB（upsert）
5. Astro 增量构建页面
6. 构建成功后发布
```

---

### 4.3 Astro 选型原因

- 原生支持 Markdown
- SSG + 混合渲染能力
- SEO 友好
- 可作为页面与组件容器

Astro 职责：
- 页面结构
- 路由
- 静态 HTML 输出

---

## 5. 前端架构设计

### 5.1 Vue 的角色定位

> **Vue 仅用于“局部交互组件”**

- 评论
- 搜索
- 交互增强

禁止：
- 全站 SPA 路由
- 作为页面生成工具

---

## 6. 后端与数据库设计

### 6.1 Spring Boot 的职责

- 提供 API
- 管理业务数据
- 内容关系建模

不负责：
- Markdown 解析
- 页面生成

---

### 6.2 数据库设计原则

- 数据库不是内容源
- 数据可从 md 重建
- 只存不可逆信息

---

### 6.3 核心数据模型（示意）

```sql
posts
- id
- slug
- published
- created_at


tags
- id
- name
- slug

post_tags
- post_id
- tag_id
```

## 7. 技术选型总结

| 层级 | 技术 | 选型原因 |
|---|---|---|
| 编辑 | Typora | Markdown 体验好 |
| 内容源 | Git | 可追溯 / 回滚 |
| 构建 | Astro | SSG + Markdown |
| 前端 | Vue | 成熟交互框架 |
| 后端 | Spring Boot | 稳定 / 工程化 |
| 数据库 | MySQL | 关系建模清晰 |

---

## 8. 风险分析与应对

### 8.1 主要风险

| 风险 | 描述 | 应对策略 |
|---|---|---|
| 构建变慢 | 内容增多 | 增量构建 |
| 数据不一致 | md / DB | 单向同步 |
| 架构偏重 | 单人维护 | 自动化 / 文档 |

---

### 阶段二

---

## 10. 总结

> 本项目不是“博客系统”，而是：
>
> **一个以内容为核心的、长期可演进的工程系统。**
>
> 当前技术选型在个人站场景下略显偏重，但在“工程训练 + 长期维护”的目标下是 **合理且有价值的**。
